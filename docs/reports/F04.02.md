## 1. Kapsam ve Yapılan Geliştirmeler

F04.02 şartnamesinde (`docs/roadmap/F04.md`) belirtilen Chrome UX Report (CrUX) gerçek kullanıcı saha verisi bağlayıcısı geliştirildi:

1. **CrUX API İstemcisi (`CruxClient`):**
   - Google Chrome UX Report API v5 (`https://chromeuxreport.googleapis.com/v1/records:queryRecord`) ile güvenli HTTP POST entegrasyonu.
   - Sayfa URL'si (`queryUrl`) ve kök alan adı / origin (`queryOrigin`) seviyesinde saha verisi sorgulama desteği.
   - PageSpeed Insights `loadingExperience` ve `originLoadingExperience` yapılarını standart `CruxResult` modeline dönüştüren adaptör (`fromPageSpeedLoadingExperience`).

2. **75. Yüzdelik Dilim (p75) ve CWV Eşik Değerlendirmesi (`CruxFieldMetrics`):**
   - Core Web Vitals ve performans metrikleri 75. yüzdelik dilim (p75) üzerinden standart eşiklerle değerlendirilir:
     - **LCP (Largest Contentful Paint):** <= 2.5s (İyi), <= 4.0s (İyileştirme Gerektirir), > 4.0s (Kötü)
     - **INP (Interaction to Next Paint):** <= 200ms (İyi), <= 500ms (İyileştirme Gerektirir), > 500ms (Kötü)
     - **CLS (Cumulative Layout Shift):** <= 0.10 (İyi), <= 0.25 (İyileştirme Gerektirir), > 0.25 (Kötü)
     - **FCP (First Contentful Paint):** <= 1.8s (İyi), <= 3.0s (İyileştirme Gerektirir), > 3.0s (Kötü)
     - **TTFB (Time to First Byte):** <= 0.8s (İyi), <= 1.8s (İyileştirme Gerektirir), > 1.8s (Kötü)
     - **FID (First Input Delay):** <= 100ms (İyi), <= 300ms (İyileştirme Gerektirir), > 300ms (Kötü)
   - Dağılım histogramları (`good`, `needs_improvement`, `poor` yüzdeleri) parse edilerek modele işlenir.
   - Genel CWV değerlendirmesi (`PASSED`, `NEEDS_IMPROVEMENT`, `FAILED`, `UNKNOWN`).

3. **28 Günlük Yuvarlanan Pencere (`CruxCollectionPeriod`):**
   - CrUX verilerinin son 28 günlük kullanıcı trafiğinden derlendiğini gösteren başlangıç/bitiş tarihleri (`firstDate`, `lastDate`) ve yerelleştirilmiş gösterim formatı (`2026-10-08 — 2026-11-04 (28 gün)`).

4. **Veri Yokluğu ve Hata Kalkanı (Fail-Safe & UNKNOWN):**
   - Yeni veya düşük trafikli sitelerde Google CrUX HTTP 404 döndürdüğünde veya metrikler boş olduğunda asla sahte `0` puan verilmez; durum `NO_DATA` ve metrikler `UNKNOWN` olarak işaretlenir.
   - Kullanıcıya açıklayıcı mesaj sunulur: *“Yeterli gerçek kullanıcı verisi bulunamadı”* (`crux.no_field_data`).
   - HTTP 429 (kota aşımı), 5xx sunucu kesintileri veya ağ zaman aşımlarında exception sızdırılmaz; `CruxResult::unavailable()` üretilir, ana SEO denetimi kesintisiz devam eder.

5. **Lab vs. Field Veri Ayrımı (Veri Kaynağı Şeffaflığı):**
   - Tüm sonuçlar `data_source: 'chrome_ux_report'`, `is_field_data: true` ve `is_lab_data: false` olarak damgalanır.
   - PSI laboratuvar simülasyonları ile CrUX gerçek saha verilerinin birbirine karışması mimari olarak engellenmiştir.

6. **Güvenli Önbellekleme (`MemoryCruxCache`):**
   - URL/Origin ve form faktörü bazında TTL destekli önbellekleme (`url#formFactor`).
   - 28 günlük pencere yapısına uygun olarak varsayılan 24 saatlik (86400s) saklama süresi ile gereksiz API harcaması önlenir.

## 5. Risk ve Güvenlik Değerlendirmesi

- **Gizli Bilgi Güvenliği:** `CRUX_API_KEY` ve `PAGESPEED_API_KEY` yalnızca ortam değişkenlerinden okunur; loglara, frontend yanıtlarına veya git deposuna sızdırılmaz.
- **SSRF Koruması:** `CruxClient`, tüm dış çağrılarda `SafeHttpClient` kullanır; DNS rebinding koruması ve URL doğrulama aktiftir.
- **Kota ve Maliyet:** 24 saatlik önbellek (`cache_ttl: 86400`) ve 404 durumlarının önbelleklenmesi sayesinde gereksiz API sorguları önlenir.
- **Rapor Güvenilirliği (T11):** Veri bulunamadığında kullanıcıya açıkça bildirim yapılır; haksız SEO cezası veya yanıltıcı 0/100 puan üretilmez.
